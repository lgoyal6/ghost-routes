# Benchmark

`make benchmark` runs `ghost-routes benchmark`, which scores four baselines against a fixed manifest and writes a report to `~/.local/state/ghost-routes/benchmarks/runs/<timestamp>/` (`report.md` and `report.json`). The command exits non-zero if a declared threshold is not met.

## Inputs

Four original synthetic sheets, generated by `ghost_routes.synthetic.plans`:

| Sheet | Family | Split | Notes |
| --- | --- | --- | --- |
| ashgrove-P-A | ashgrove-P | dev | stair repair, one fence |
| ashgrove-Q-A | ashgrove-Q | held out | trench, two fences |
| ashgrove-Q-B | ashgrove-Q | held out | revision B adds a third fence |
| lyndale-A | lyndale | held out | rotated and scaled layout, two phases |

The split is by plan family, so no held-out sheet shares a layout with the dev family. `benchmarks/manifest.json` records each PDF's SHA-256, and a run refuses to start if a regenerated input differs. Labels in `benchmarks/labels/` come from the generator's ground truth, never from model output. Title-block, header and scale text is labeled `context`. Predictions on context text are neither credited nor counted as false positives.

The real Iowa sheet J.01 is listed but not scored: no human-checked labels exist for it yet, so it is reported as counts, not accuracy.

## Baselines

| Baseline | What it is | Needs the model |
| --- | --- | --- |
| `native_text` | Rules over native PDF text only. Cannot propose path or barrier geometry or place names; those groups are reported as unsupported, not dropped. | no |
| `raw_vlm` | The model's JSON taken at face value: no anchoring, phase or dimension checks. | yes |
| `full_pipeline` | The same model responses through the validator used in production. | yes |
| `manual_graph` | Hand-built graphs with known outcomes through the same verifier and repair engine. Isolates extraction error from verification error; it is not evidence that extraction works. | no |

`raw_vlm` and `full_pipeline` share one inference per crop, cached under `~/.local/state/ghost-routes/benchmarks/cache/` and keyed by the crop image, model digest, prompt and options. `ghost-routes benchmark --no-live` runs the two no-model baselines and reports the model baselines as not run.

## Metrics

Classes that answer the same reviewer question are scored together: `legend_entry` and `phase_label` as phase text; `crossing` with `path`. Matching is one-to-one, closest pairs first:
- Text matches when the box centers are within 24 pt.
- Geometry matches when the Hausdorff distance is within 15 pt (2.5 m on these sheets).

Each run reports:
- **Precision and recall, per group, with their counts.** Rates are recomputed from summed counts, never averaged.
- **Phase assignment:** matched items whose phase set equals the label's.
- **Dimension values:** the matched value within 1 mm.
- **Median localization and geometry error,** in metres.
- **False connections:** predicted paths joining two true nodes that no true path joins.
- **Flagged for review:** predictions carrying a validator flag.
- **Correction burden:** false positives to reject, plus misses to add, plus wrong phases to edit.
- **For the hand-built graphs:** status correctness and false-supported outcomes.

Model self-confidence is not used anywhere: it is not a calibrated probability.

## Thresholds

Declared in the manifest before any held-out evaluation:
- `manual_graph`: status correctness 1.0, and zero false-supported outcomes.
- `full_pipeline` on held-out sheets: zero false connections, phase-text recall at least 0.6, and note recall at least 0.5.

Changing inputs, labels or thresholds means editing `HISTORY` in `ghost_routes/benchmark/manifest.py` with whether any model result had been seen, then running `ghost-routes benchmark --write-manifest`. A unit test fails if the tracked manifest drifts from the generator.

## Results of the first live run (2026-10-31)

Model `qwen2.5vl:7b`, digest `5ced39df…`, prompt `gr-extract/4`, validator `gr-validate/2`, 24 crops at about 40 s each. These are the held-out sheets (Q-A, Q-B, Lyndale), with counts as true positives / false positives / false negatives:

| Group | Native text | Raw model | Full pipeline |
| --- | --- | --- | --- |
| Notes | 1 / 3 / 6 | 7 / 11 / 0 | 7 / 11 / 0 |
| Phase text | 7 / 0 / 6 | 12 / 40 / 1 | 12 / 20 / 1 |
| Dimensions (value right) | 3 / 0 / 0 (3 of 3) | 3 / 0 / 0 (2 of 3) | 3 / 0 / 0 (3 of 3) |
| Place labels | unsupported | 6 / 2 / 0 | 6 / 2 / 0 |
| Paths | unsupported | 0 / 3 / 21 | 0 / 3 / 21 |
| Barriers | unsupported | 0 / 12 / 7 | 0 / 12 / 7 |
| Correction burden | 49 | 97 | 77 |

On the hand-built graphs, the verifier got 15 of 15 statuses right, with 0 false-supported outcomes and 7 of 7 repair statuses.

What this shows:
- **The model reads text well.** It finds every note and almost all phase text, and every phase assignment it made was correct.
- **Precision is poor.** Overlapping crops repeat the same item, and the model also invents phase labels. The validator halves the false phase-text proposals and corrects one dimension value, but it cannot make the output precise.
- **Geometry does not work.** The model found none of the 28 path and barrier labels. "Zero false connections" holds only because it proposed almost no paths.
- **Flags do not discriminate.** 76 of the 79 pipeline proposals carry a flag, so a flag does not separate good proposals from bad ones.
- **The thresholds were met, but they were weak.** They measured recall and false connections, not precision or geometry. The manifest history records this note, written after the results were seen. The thresholds themselves were not changed.

The full report is in `~/.local/state/ghost-routes/benchmarks/runs/`.
